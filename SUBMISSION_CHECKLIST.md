# Submission checklist

Vaibhav runs this with Prit before the final push (planned for Fri 27 Nov, 11:00 IST). Every box must be ticked.

## 1. Automatic checks

```bash
python tools/check_rules.py
python validate.py
```

- [ ] `check_rules.py` prints PASSED, and every WARNING has been read
- [ ] `validate.py` passes

## 2. Fresh clone test

Use a new, empty folder on a different machine if possible.

```bash
git clone <our-repo-url> fresh-check
cd fresh-check
git lfs pull
git lfs ls-files --size
OMP_NUM_THREADS=1 python validate.py
git status --porcelain
```

- [ ] Weights download and have their real size (not a tiny text pointer file)
- [ ] `validate.py` passes on the fresh clone
- [ ] `git status --porcelain` prints nothing (the run changed no repo files)
- [ ] Average time per decision is about 40 ms or less with 1 CPU thread
- [ ] The agent also loads on a machine with no network

## 3. Checks a script cannot do (Prit reads the code)

- [ ] No hand-written behaviour: nothing in `submission/` picks, overrides or filters actions except the network's output
- [ ] `reset()` clears the recurrent state, memory map, landmark slots, last action and counters
- [ ] The policy receives no privileged training information
- [ ] The final checkpoint was evaluated on the unmodified environment
- [ ] `env/`, `validate.py` and the base image files are unchanged from the template
- [ ] All code was written during the hackathon; every map not generated by us is listed in `train/MAP_SOURCES.md`
- [ ] Memory buffers have a fixed size, so long maps cannot run out of RAM or VRAM

## 4. Repository and deliverables

- [ ] Repo is public (opens in a private browser window without signing in)
- [ ] Created from the official starter template during the hackathon
- [ ] Total size is 1 GB or less, including Git LFS
- [ ] No tokens or passwords in the files or commit history
- [ ] Training code is included
- [ ] No Dockerfile of our own
- [ ] `submission/requirements.txt`, if present, has only approved packages with pinned versions
- [ ] 2-page PDF brief covers selling point, architecture, spatial memory, training and exploration
- [ ] Every number in the PDF comes from a real run
- [ ] Organizer answers are saved with proof (`docs/ORGANIZER_CLARIFICATIONS.md`)

## 5. After the push

- [ ] Write down the final commit ID: `git rev-parse HEAD`
- [ ] Nobody pushes anything else
